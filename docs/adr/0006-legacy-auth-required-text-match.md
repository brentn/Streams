# Synthesize a code for legacy "auth required" errors instead of leaving them unclassified

`classifySyncStatus` deliberately keys off `errlist`'s `code` field only, never `msg` text, since the SimpleFIN protocol spec gives message text no normative meaning — `CONTEXT.md`'s Needs Reauthentication definition said as much. In practice, CIBC's bridge sends `"Connection to CIBC may need attention. Auth required"` through the deprecated v1 `errors` string array, which has no code at all (`fetchAccounts` maps it to `{ code: '', msg }`), so it can never match `con.auth`/`gen.auth` and permanently surfaces as a generic Sync Issue warning ("Retry") instead of Needs Reauthentication ("Reconnect") — even though the connection is, in fact, broken and needs the user to go reconnect. We decided to add a narrow, case-insensitive `/auth required/i` match for legacy code-less entries only (not for entries that already carry a real, non-auth code — an explicit code is trusted over inferred text), synthesizing a made-up `legacy.auth-required` code at the point where legacy strings are translated into `SimpleFinError`s (`simplefin-adapter.ts`'s `legacyErrors` mapping), and adding that synthetic code to `AUTH_ERROR_CODES`. `classifySyncStatus` itself stays untouched and still purely code-based — the text inference is contained to one boundary, not smeared into the core classifier. We chose a narrow exact-phrase match over a broad `/auth/i` match because the two failure modes are asymmetric only within limits: a broad match risks false-triggering Reconnect on unrelated legacy messages, while a narrow match can miss differently-worded auth failures from other legacy-only bridges — we accepted the narrower, safer match for now and can widen it if other bridges' phrasing turns up.

## Consequences

- The "never inferred from message text" invariant now has one documented, narrow exception, scoped to legacy code-less entries only — `CONTEXT.md`'s Needs Reauthentication entry was updated to describe it precisely rather than leave it as a silent contradiction.
- Only the exact phrase "auth required" (case-insensitive) is recognized; a legacy-only bridge phrasing its auth failure differently (e.g. "please re-authenticate") will still fall through to a generic Sync Issue until that phrasing is added.
- No new UI: Needs Reauthentication already routes to the existing `/connect` "paste a new setup token" flow (ADR-0002's static client-only architecture means Streams never brokers an in-app OAuth-style reauth window regardless of classification).
