# Uncategorized tributaries bucket by calendar month and direction, not one per Transaction

Ticket #63 shipped `buildUncategorizedTributaries`, rendering one tributary per unmatched Transaction, each individually labeled "Uncategorized." Code review flagged this as visually noisy for accounts with many small unmatched Transactions, and it left #67 ("Tributary legibility for tiny amounts / high flow count") assuming a genuine aggregate-tributary shape from ticket 2 that didn't actually exist yet. We decided instead to bucket unmatched Transactions by calendar month and direction: two aggregate tributaries per month (uncategorized income, uncategorized expense), each occurring on the 1st of that month, sized by the summed amount of the Transactions in that bucket, rendered only for months with at least one bucketed Transaction — not every period the way a real Budget-kind Flow always renders one. Both buckets keep the plain "Uncategorized" label; direction is communicated by the tributary's existing geometry/color convention, same as every other Flow/Transfer tributary, so no direction suffix and no count badge (unlike #67's planned ×N rollup badge for magnitude-based clustering) — thickness alone communicates volume. This is deliberately *not* modeled as a domain Budget: there's no user-set limit, no Tolerance, no Variance Alerts, and unlike a Budget's single fixed `direction`, uncategorized activity is inherently mixed-direction — it's a rendering-only aggregation, not a new Flow kind.

This amends #63's shipped implementation of `buildUncategorizedTributaries`, which is superseded rather than kept alongside this, and unblocks #67, which depends on this aggregate shape already existing.

## Consequences

- The always-visible uncategorized-transaction list stays unwindowed (shows every pending Transaction regardless of the account screen's current scrub position) while its tributaries remain windowed to the visible ~60-day range — the same tradeoff `buildTributaries` already accepts for every real Flow/Transfer occurrence. An old unmatched Transaction can appear in the list with no currently-visible tributary if the user has scrubbed far from its month.
- An account with many small unmatched Transactions in one month sees a single bucketed line instead of many individual ones, trading away per-transaction chart detail (still reachable by clicking through to the list) for legibility.
