# Shrink SimpleFIN sync lookback to 40 days to preempt the 45-day advisory limit

Issue #56 set `MAX_SYNC_LOOKBACK_DAYS` to 85 — a 5-day margin under SimpleFIN Bridge's hard 90-day range limit. In practice, SimpleFIN Bridge also returns a separate, softer warning on every request past 45 days: `"Requested date range exceeds recommended range of 45 days. In the future, this may be capped."`, surfaced verbatim as a user-visible Sync Issue banner. We decided to shrink `MAX_SYNC_LOOKBACK_DAYS` to 40 (same 5-day margin logic applied to the new 45-day threshold) rather than suppress or ignore the warning, since SimpleFIN's own wording says this may become a hard-enforced cap later — complying now avoids a repeat of this same fix once it does. To keep a manual resync's total backfill reach roughly unchanged despite the smaller per-chunk window, `MAX_BACKFILL_CHUNKS_PER_RESYNC` went from 5 to 10 (10×40 ≈ 5×85 ≈ 14 months). We kept this a single static global constant rather than adaptive/per-institution logic, consistent with ADR-0003's single-connection model — there's no evidence the 45-day figure is institution-specific, and reacting dynamically to the warning would add state to solve a problem the constant already solves.

## Consequences

- A full backfill sweep now costs 10 requests per manual resync instead of 5, to close the same historical gap in roughly the same number of resync clicks — still within ADR-0004's ~24 requests/day SimpleFIN Bridge quota for a single resync click, but it leaves less daily headroom if a user clicks resync more than once or twice in a day.
- The existing "90-day hard limit" margin reasoning in `sync-window.ts`'s comments becomes moot in practice (40 is well under both the 45-day advisory and 90-day hard limit) but is left in place as the fallback protection it always was.
